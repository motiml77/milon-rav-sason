# תיוג מושגים — מה נכנס לאתר ומה לא

## נכנס: `synonyms.json` — הרחבת מילים נרדפות

`vocabulary.json` מחזיק 135 מושגי־יסוד, כל אחד עם הניסוחים החלופיים שלו
(`כתר` = `אור הכתר` = `חיוורתי` = `הלובן העליון` = `רדל"א`).
`build_synonyms.py` הופך את זה ל-135 קבוצות / 1014 ניסוחים,
ו-`build_search_index.py` מצרף אותן ל-`search-index.json` בשדה `syn`.

בחיפוש (`milon.html`, ליד `SYN_TIER`) זה עובד כ**נספח בלבד**:

| תנאי | ערך |
|---|---|
| מופעל רק כשהתוצאות דלות | `results.length < 25` |
| רק כש*כל* השאילתה היא מושג מוכר | לא הרחבה של מילה בודדת מתוך משפט |
| מקבל רק התאמות כותרת חזקות | `tier <= 2` |
| תקרה קשיחה | 12 תוצאות |
| דרגה | `SYN_TIER = 90` — גבוה מכל דרגה אמיתית, ולכן תמיד אחרון |

לכן התוצאות המקוריות **לא זזות**: הן כבר מוינו וננעלו לפני שהנספח מתווסף,
והנספח מכיל רק ערכים שהחיפוש המקורי לא מצא כלל.
נמדד: 0 שינויים בסדר, ציון ערכת הבקרה נשאר 98.78.

אם `synonyms.json` נמחק — החיפוש חוזר להתנהג בדיוק כמו קודם.

## לא נכנס: `entry-tags.json` — תיוג לפי מושגים

תיוג של 697 ערכים לפי אותם 135 מושגים, שנועד לשמש ל"ערכים קשורים".
**נפסל במדידה, אל תחברו אותו:**

- יחס משוקלל-IDF: **4.4** (הסף שנקבע מראש היה ≥10)
- דירוג חציוני של השותף האמיתי: **86 מתוך 697**
- רק **15%** מהזוגות הנכונים הגיעו לעשירייה הראשונה

הסיבה: 135 מושגים על 698 ערכים זה גס מדי. `מלכות` לבדו מתייג 192 ערכים (28%),
כך ש-29% מכל זוג אקראי חולק תגית. תגית שכמעט כולם חולקים לא מבדילה בין כלום.

`measure_tags.py` מריץ את המדידה הזאת מחדש.
